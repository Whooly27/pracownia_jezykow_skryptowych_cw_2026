# Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sekcja 4.1 Files ze spec (czwarta wersja, 7.11): `GET /files`, rename, delete, remove-access, download, plus dopasowanie tego, co spec zmieniła w obiekcie File i w `POST /uploads`.

**Architecture:** Nowe widoki w `apps/files/views.py` na tych samych helperach co upload (`api_view`, `ApiError`, `file_to_json`, `access_for`). Lista plików to jedna funkcja budująca queryset z parametrów i keyset-paginacja po `(sort, id)`. Download to podpisany GET w `Storage` (jak PUT), obsługiwany przez tę samą atrapę `_blob`.

**Tech Stack:** Django 5.2, Postgres, pytest-django, ruff, mypy strict. Wszystko w `apps/backend`.

**Spec:** `docs/openbox-technical-specification.md` (sekcja 4 od linii 198; 4.1 Files od 227, 4.2 Uploads od 398). Design doc poprzedniego brancha: `docs/superpowers/specs/2026-11-07-upload-design.md` (decyzje: bez DRF, csrf_exempt, sesja Django, nazwy case-sensitive, atrapa Vercel Blob).

## Co zmieniła czwarta wersja spec (względem kodu w main)

- Obiekt File: `owner_id` (string) zamiast `owner {id, display_name}`; `is_shared` (bool: ktoś poza właścicielem ma dostęp) zamiast `member_count`. `viewer` znika z `GET /files`.
- `POST /uploads` przyjmuje jeden plik `{name, size_bytes, mime_type}` i zwraca jeden obiekt Upload w `data`; odrzucenie to kod HTTP: 409 `name_conflict`, 413 `file_too_large`, 415 `unsupported_file_type`, 422 `validation_failed`.
- 422 `validation_failed` "lists one error per problem": `errors` może mieć kilka wpisów.
- Komunikat 404: `File <id> doesn't exist or you can't see it.`

## Global Constraints

- Koperta `{"data": ..., "errors": [...]}`; 204 bez ciała.
- Kody i statusy dokładnie jak w tabelach spec 4.1 i 4.2.
- `GET /files`: `limit` 1 do 200, domyślnie 50; `sort` `name` (domyślnie) lub `modified_at`; `order` `asc` (domyślnie) lub `desc`; `q` co najmniej 2 znaki; najwyżej jeden z `shared_with_me`, `shared_by_me`, `q`.
- Download: URL ważny 60 sekund, zapisuje pod prawdziwą nazwą (Content-Disposition attachment).
- Bez DRF, bez background jobs, bez zmian w modelach (żadnej nowej migracji).
- Komentarze i teksty bez długiej pauzy, półpauzy i interpunktu.
- `ruff check`, `ruff format --check`, `mypy .`, `makemigrations --check` czyste; testy tylko reguł domenowych.

## Review Focus

1. Dwa pliki o tej samej nazwie u różnych właścicieli na jednej stronie `shared_with_me`: paginacja po `(name, id)` nie gubi i nie dubluje żadnego; test w Task 3.
2. `after` wskazujące plik, który istnieje, ale nie jest w tej liście (np. cudzy, nieudostępniony): 422 `invalid_after`, nie 200 z pustą stroną; test w Task 3.
3. Rename na tę samą nazwę co obecna: 200, nie 409; test w Task 4.
4. Usunięcie pliku przez grantee z `delete`: znikają też linki i granty innych osób, bajty też; test w Task 5.
5. Link do pobrania po 60 sekundach: 403 z `_blob`; test w Task 6.

### Task 3: `GET /files`

**Files:**
- Create: `apps/backend/apps/files/views.py`, `apps/backend/apps/files/listing.py`, `apps/backend/apps/files/urls.py`, `apps/backend/apps/files/tests/test_list_files.py`
- Modify: `apps/backend/config/urls.py` (`path("api/v1/", include("apps.files.urls"))` obok uploads)

**Interfaces:**
- Produces:
  - `listing.py`:
    - `@dataclass(frozen=True) class ListQuery: scope: Literal["mine","shared_with_me","shared_by_me","search"]; q: str; sort: Literal["name","modified_at"]; order: Literal["asc","desc"]; limit: int; after: UUID | None`
    - `def parse_query(params: QueryDict) -> ListQuery`: zbiera wszystkie problemy i rzuca `ApiError(422, "validation_failed", messages=[...])`. Filtr liczy się, gdy wartość to dokładnie `"true"`; inna wartość to problem. `after` niebędące UUID to problem.
    - `def base_queryset(user: User, query: ListQuery) -> QuerySet[File]`: mine `owner=user`; shared_with_me `grants__user=user`; shared_by_me `owner=user, grants__isnull=False`; search `(owner=user | grants__user=user) & name__icontains=q`; zawsze `.distinct()`.
    - `def page(user: User, query: ListQuery) -> tuple[list[File], bool]`: sortowanie `(sort, id)` w kierunku `order`; gdy `after`: plik musi być w `base_queryset` (inaczej `ApiError(422, "invalid_after", "after isn't a file in this list; reload from the start.")`), potem warunek keyset `Q(sort__gt=v) | Q(sort=v, id__gt=after.id)` (dla desc `lt`); pobiera `limit + 1`, zwraca `(items[:limit], len(items) > limit)`.
  - `views.list_files(request) -> HttpResponse` (`@api_get`): `ok({"upload_policy": upload_policy() if scope == "mine" else None, "items": [file_to_json(f, user) ...], "has_more": more})`.
  - `urls.py`: `app_name = "files"`, `path("files", views.list_files, name="list")`.

### Task 6: Download

**Files:**
- Modify: `apps/backend/apps/uploads/storage.py` (Protocol + atrapa), `apps/backend/apps/uploads/blob_views.py` (GET), `apps/backend/apps/uploads/tests/test_storage.py`, `apps/backend/apps/files/views.py`, `urls.py` (`files/<uuid:file_id>/download`)
- Create: `apps/backend/apps/files/tests/test_download.py`

**Interfaces:**
- Produces:
  - `Storage.get_url(self, key: str, filename: str, expires_at: datetime) -> str`.
  - `LocalBlobStorage.get_url`: token `signing.dumps({"key", "filename", "expires_at"}, salt=GET_TOKEN_SALT)` (`GET_TOKEN_SALT = "blob-get"`), URL `f"{BLOB_BASE_URL}/api/v1/_blob/{key}?token=..."`.
  - `blob_views.blob(request, key)`: `require_http_methods(["GET","PUT"])`; PUT jak dziś (`put_blob` zostaje jako funkcja wewnętrzna), GET: token z solą GET, 403 gdy zły/klucz inny/po terminie, 404 gdy brak pliku, `FileResponse(path.open("rb"), as_attachment=True, filename=filename, content_type=<z .mime>)`.
  - `DOWNLOAD_TTL = timedelta(seconds=60)` w `apps/files/views.py`; `download_file(request, file_id)`: `not_found` gdy brak dostępu; `expires_at = now + DOWNLOAD_TTL`; `ok({"url": storage.get_url(file.storage_key, file.name, expires_at), "expires_at": iso(expires_at)})`.
